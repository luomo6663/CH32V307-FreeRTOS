# 舵机控制

## 接线和实板差异

| 通道 | MCU / 定时器 | 右侧接口 | 左侧接口 |
| --- | --- | --- | --- |
| A | PB4 / TIM3_CH1 | H21 | H5 |
| B | PB5 / TIM3_CH2 | H3 | H6 |
| C | PB0 / TIM3_CH3 | H4 | H7 |

PD2 为 ARM_SWITCH，参照 code_2 默认高电平选右侧，低电平选左侧；接线相反时修改
`ROBOT_SERVO_SIDE_INVERT`。CH440R 整组切换三路信号，当前实现一次只给一侧
发送 PWM，另一侧的实际位置和保持力矩不能由固件保证。

原理图有六个三针接口，但用户提供的实板照片只有五个已焊接口，另有空焊盘。
尚不能确认缺少哪个 H 接口。默认保留六个原理图逻辑接口可用于接线核实，
`SERVO MAP` 显示 `UNVERIFIED`；这不表示软件检测到了六个舵机。

每个三针接口原理图定义为：1=GND、2=VSER_A/B/C、3=PWM。实际插接朝向以
PCB 丝印和测量为准。主板的 U17 是八针线束口，与六个舵机插座是不同接口。
舵机板通过降压电路产生 VSER 电源，不能将主板线束的 12V 当作舵机信号电压。
原理图片段中 CH440R 的 EN#（15 脚）画有接地，旧文档“悬空”说法已纠正。

## 默认启动

- 参照 code_2 使用 300 Hz，约 3333 us 一帧，脉宽计时分辨率 1 us。
- 默认右侧，三个已配置通道输出各自中位（默认 1500 us）。
- 启动先发送一帧全低电平，再从完整帧开始输出中位，避免初始化拉长首个脉冲。
- 当前 `ROBOT_SERVO_BOOT_TEST=1`：上电右侧 A/B/C 同时执行一次全范围测试，1500→500（1.5 秒）→2500（3 秒）→1500 us（1.5 秒），结束后保持中位，不循环。左侧不参与。
- USART3 自动输出每路测试的开始、最小脉宽、最大脉宽、回中完成或中止记录。记录表示软件 PWM 指令进度，不是实测轴位置。
- HOLD/OFF 或新的通道动作指令会取消涉及通道的上电测试，切换侧别也会取消旧侧测试。将 `ROBOT_SERVO_BOOT_TEST` 设为 0 可恢复仅输出中位的启动行为。
- 以后切换恢复该侧最后的软件脉宽和输出开关状态，不恢复运动或扫描。
- 没有舵机位置反馈；所有脉宽和运动完成状态都是指令状态。

## 串口命令

USART3，115200-8-N-1，命令不区分大小写，每条以换行结束。

| 命令 | 行为 |
| --- | --- |
| `SERVO` / `SERVO MAP` | 显示映射、各侧状态、限位、队列、实际选择电平及定时器 |
| `SERVO HELP` | 打印舵机命令帮助 |
| `SERVO SIDE` | 查看状态 |
| `SERVO SIDE R` / `SERVO SIDE L` | 请求选择右侧/左侧，支持 RIGHT/LEFT |
| `SERVO A 1600` | 当前侧 A 路设置 1600 us；B/C 同理 |
| `SERVO ALL 1500` | 当前侧所有已配置通道设置 1500 us |
| `SERVO 1500` | 兼容旧命令，只设置当前侧 B 路 |
| `SERVO CENTER [A\|B\|C\|ALL]` | 输出各通道的校准中位，省略通道表示 ALL |
| `SERVO MOVE A 1700 1000` | A 路从当前软件脉宽线性移动到 1700 us，持续 1000 ms |
| `SERVO MOVE ALL 1600 1000` | 当前侧各通道同时移动到 1600 us |
| `SERVO POSE 1500 1600 1400 1000` | A/B/C 分别移动到三个目标，同用 1000 ms |
| `SERVO HOLD [A\|B\|C\|ALL]` | 停止相应通道的插值或扫描，继续输出当前软件脉宽 |
| `SERVO OFF [A\|B\|C\|ALL]` | 停止相应通道的 PWM，软件脉宽保留 |
| `SERVO SWEEP A 1400 1600 2000` | A 路在 1400–1600 us 之间做周期 2000 ms 的三角扫描 |
| `SERVO SWEEP ALL 1400 1600 2000` | 当前侧所有已配置通道扫描 |
| `SERVO SWEEP [ms]` | 兼容旧命令，当前侧全部按默认 1000–2000 us 扫描 |

`ALL` 始终仅指当前侧的已配置通道。单独访问被配置为缺失的通道会报错。
MOVE 的时间可为 0（直接设定），最大 600000 ms；SWEEP 周期最小 20 ms。
扫描在收到并应用指令时直接从下限开始，是显式台架检查功能。
设置脉宽、MOVE、POSE、CENTER、SWEEP 会重新开启涉及通道的 PWM；HOLD 不会
重新开启已 OFF 的通道。OFF 不切断舵机电源，也不是机械刹车。

常用交互统一使用上表的单行脉宽命令，每条以换行结束，无需进入菜单。
A 对应爪子，B 对应中间关节，C 对应底部关节，与 code_2 的 UP/MID/DOWN 对应。
旧的 `SERVO ANGLE <A|B|C|ALL> <-135..135> <ms>` 保留兼容，常用帮助以脉宽为主。

脉宽和时间参数必须是完整十进制非负整数，脉宽范围为 500–2500 us，且必须符合每个通道
的配置限位。多通道命令全部校验成功才入队，不会部分执行；多余参数、尾随
字符、超大数字、逆序扫描范围等都会拒绝。

## 命令时序和状态

`ok servo queued` 表示命令进入 FIFO，不表示机械动作已经完成。队列容量为
16 条，满时返回 `queue full`，不会静默覆盖。控制任务每 10 ms 应用一条命令。
连续发送的 SIDE 和目标命令按顺序执行，参数按之前已入队的 SIDE 对应配置校验。
运动命令会替换涉及通道正在进行的动作，不等待前一个动作到达终点。

TIM3_CH1/2/3 使用比较预装载。CH4 不输出到 PB1，只在每帧第 3000 us 产生
提交中断；此时最大 2500 us 舵机脉冲已经结束。中断提交三路下一帧脉宽，并
在需要时改变 PD2。新脉宽在下一次计数器溢出时生效。若中断延迟到脉冲区间
或距溢出不足保护间隔，跳过该次提交并等待后续帧。300 Hz 配置的保护间隔为
100 us；周期足够长时为 1000 us。

因此命令有任务和帧同步延迟，OFF/HOLD 也不是立即生效的急停。切换过程中
暂停消费后续命令，等低电平区间完成路由后继续；停止旧侧所有运动，其余一侧
的命令和 PWM 不会因扫描在后台持续推进。

状态中的 `requested` 为最后入队的侧别，`control` 为控制任务已应用的侧别，
`routed` 为已经写入 PD2 的侧别；下一帧才开始输出新路由脉冲。
`cmd/target` 为软件脉宽，不代表轴角度；CCR 是预装载寄存器，不代表位置反馈。
未选中的侧别即使显示 `pwm=on`，也只是保存的输出启用状态，没有持续收到 PWM。

## 配置与标定

配置集中在 `User/config/robot_config.h`，重新编译后生效，不提供 Flash 写入：

- `ROBOT_SERVO_DEFAULT_SIDE_RIGHT`：默认右侧为 1。
- `ROBOT_SERVO_BOOT_TEST`：上电一次全范围动作，当前测试固件设为 1；使用各通道配置的最小、中位和最大脉宽。
- `ROBOT_SERVO_RIGHT_INSTALLED_MASK` / `LEFT_INSTALLED_MASK`：位 0/1/2 对应 A/B/C。
- `ROBOT_SERVO_MAP_VERIFIED`：接口是否已经人工核实，信息标记，不是自动检测。
- `ROBOT_SERVO_MIN_US_TABLE` / `CENTER_US_TABLE` / `MAX_US_TABLE`：两行三列，
  第 0 行右侧、第 1 行左侧，列按 A/B/C 排列。
- `ROBOT_SERVO_SIDE_INVERT`：选择电平反转。
- `ROBOT_SERVO_MAX_MOTION_MS`：运动和扫描周期上限。

例如仅在实测确认左侧 C/H7 未焊之后，才将 LEFT_INSTALLED_MASK 改成 `0x03U`，
并在核实其余接口后将 MAP_VERIFIED 改为 1。此示例不表示当前照片缺的是 H7。

脉宽配置必须满足 `500 <= min <= center <= max <= 2500`。配置无效时保持 PWM
为零，并拒绝运动指令。机械允许行程通常小于舵机标称电气行程，标定后应收紧
各自限位。1500 us 表示电气中位，不能保证装配后的机械关节正好居中。

## 核实接口的方法

1. 断电，用通断档核对五个已焊接口的 GND、VSER 和信号路径，记录缺失 H 编号。
2. 更新安装掩码；逐个检查舵机电源电压与共地。
3. 空载或解除机构约束，上电确认默认右侧及中位。
4. 先执行 `SERVO OFF ALL`，再单独 `SERVO A 1500`，观察对应插座的 PWM。
5. A/B/C 逐路核实后，切到左侧重复核实。未选侧不保证保持力矩。
6. 使用中位附近的小范围 MOVE，核实方向及行程，再设置每个接口的机械限位。

## 验证

主机逻辑测试（需要 PATH 中的 GCC，或传 `-Compiler` 指定路径）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\test_servo.ps1
```

测试编译实际驱动和实际控制台舵机处理函数，使用主机 GPIO/定时器替身，覆盖
插值、单路扫描、HOLD/OFF、命令顺序、切换低电平窗口、超时和 tick 回绕、
队列满、缺失接口、校准限位、极性反转、无效配置和严格参数解析。
替身不模拟真实定时器预装载时序、ISR 延迟、CH440R 电气行为或舵机负载。

固件构建仍使用 `tools/build.ps1`。上板还需示波器验证三路频率/脉宽、OFF
输出低电平、左右切换没有截断脉冲，并验证电机和转台同时运行时无资源冲突。
未进行上板实测时，不能将主机测试结果当作上述硬件验收结论。
